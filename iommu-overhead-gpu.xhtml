판정

Green측정 완료 GPU 메모리 버퍼에서 uio(IOMMU off) 대비 vfio(IOMMU on)의 IOMMU 오버헤드는 측정 노이즈 이하다. 24쌍(러너 2 × 패턴 2 × qdepth 6) 전체의 IOPS delta가 -0.5% ~ +2.7%다. +2%대 값은 uio/vfio가 서로 다른 부트·런에서 나온 편차지, IOMMU를 켜서 빨라진 것은 아니다.

조건

  • 머신: sid(192.168.100.4). NVMe 16대를 GPU와 같은 NUMA 노드에 고정
  • 디바이스: 0000:4d:00.0 ~ 0000:54:00.0, 0000:67:00.0 ~ 0000:6e:00.0
  • 부트: uio = intel_iommu=off, vfio = intel_iommu=on iommu.strict=1
  • 경로: uio는 uio_pci_generic, vfio는 vfio-pci + iommufd
  • 스택: xNVMe + uPCIe(upcie-cuda) + CUDA dmabuf
  • 워크로드: randread 4K, read 128K, qdepth 1/2/4/8/16/32, 런타임 30 s × 5회
  • 러너: xnvmeperf(단일 프로세스에서 16대 개방) / fio(디바이스당 별도 프로세스)

측정

표의 IOPS는 16대 합산, 5회 반복 평균. delta = (vfio - uio) / uio. 합산 최대는 randread에서 약 5.16M IOPS(약 20.2 GiB/s), 순차읽기에서 약 20.4 GiB/s다.

한계

  • read 128K는 qdepth 1에서 이미 약 20.3 GiB/s로 GPU PCIe 링크를 포화시킨다. 이 구간의 delta 0%는 링크가 말한 것이지 번역 비용이 없음을 증명하지 못한다. 해석 가능한 지점은 서브-포화인 randread 4K qdepth 1/2다.
  • fio의 +1 ~ +2.7%는 uio/vfio가 서로 다른 부트·런에서 따로 수집된 데 따른 실행 간 편차다.
  • GPU 숫자가 실제 P2P인지(BAR1 사용)는 nvidia-smi -q -d memory 검증을 마치지 않았다. 버퍼가 시스템 메모리로 빠졌을 가능성이 남아 있다.

요청

GPU 메모리 조건(uio_gpu·vfio_gpu) 수집은 끝났다. 남은 확인은 nvidia-smi 기반 BAR1 사용량 검증이다. 호스트 메모리 조건(uio_host·vfio_host)까지 수집해 4-조건 보고서를 낼지 알려달라.
