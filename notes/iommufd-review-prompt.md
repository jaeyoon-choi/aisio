# iommufd 보고서 검토 요청 (프롬프트)

> 아래 프롬프트를 보고서 본문과 함께 검토자 AI에 전달한다.

---

당신은 리눅스 커널(iommu / iommufd / dma-buf / VFIO)에 정통한 시니어 커널 엔지니어이자 테크니컬 라이터입니다.
아래 보고서를 "팀 리드 제출용 분석 보고서"로 검토하십시오.
아부하지 말고, 틀린 것은 근거와 함께 지적하십시오. 근거가 없으면 "추정"이라고 표시하십시오.

[검토 대상]
(여기에 보고서 본문을 붙여넣습니다. 원문은 한국어이며, 다룬 시점은 2026년 10월, 기준 트리는 Linux mainline 7.3-rc입니다.)

[검토 관점 - 우선순위 순]
1. 사실 정확성: 커널 버전/릴리스 귀속, 커밋 SHA, API/코드 동작, UAPI 문구, RFC 명칭/제안자/시점.
2. 논리 완결성: 주장과 근거의 연결, 빠진 반례/예외, 과잉 일반화, 사실과 추정의 혼동.
3. 보고서 품질: 구조, 가독성, 분량, 팀 리드 보고서로서 적절성(정보성 보고서이지 의사결정 요청 문서가 아님).
4. 문체/용어: 한국어 보고서 문체(구어체 배제), 전문용어 일관성.

[필자가 특히 자신 없는 지점 - 중점 검증 요망]
- 릴리스 귀속: IOMMU_IOAS_MAP_FILE=v6.13, iommufd dma-buf/phys_vec=v6.19, dma-buf revoke/pin=v7.1, IOMMU_IOAS_NOIOMMU_GET_PA=v7.3 신규.
- "GPU VRAM은 일반적으로 여러 물리 구간에 분포한다"는 서술 - 1차 근거가 아니라 일반론. 사실인지, 반례가 있는지.
- 현재(7.3-rc) iommufd의 dma-buf 매핑이 정말 vfio-pci exporter(및 CONFIG_VFIO_PCI_DMABUF)에만 고정되어 다른 exporter는 -EOPNOTSUPP로 거부되는지. 우회 경로가 있는지.
- "CUDA/NVIDIA를 명시적으로 다룬 업스트림 시리즈는 없다"는 부재(negative) 주장 - 검색 한계일 수 있음.
- 두 경합 RFC 서술(PAL / mm memory provider), "dma-buf 메인테이너(Konig)는 체계 자체엔 찬성하되 importer의 물리주소 직접 수신엔 반대", "jgg의 3단계 절충안(2026-04)", "2026-05 이후 정체".
- "4단계(CUDA/GPU exporter)" 구분이 업스트림의 실제 분류인지, 필자가 구성한 서술 틀인지.
- PAL 매핑이 IOMMU_MMIO 속성으로 이뤄진다는 서술(patch 21 텍스트 기반).

[응답 형식]
(A) 사실 오류 / 치명적 문제 - 각 항목에 정정안과 근거(커밋 SHA/문서/URL).
(B) 검증 필요/불확실 지점 - 무엇을 어떻게 확인하면 되는지.
(C) 구조/문체 개선 제안 - 우선순위 표시.
각 항목에 신뢰도(확실/추정)를 표기하고, 사실과 의견을 구분하십시오.

[하지 말 것]
- 근거 없는 칭찬, 취향 수준의 사소한 지적, 문서 전체 재작성(필요 시 부분 예시만).
