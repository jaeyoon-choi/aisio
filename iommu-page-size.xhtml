개요

IOMMU-off(uio_pci_generic)와 IOMMU-on(vfio-pci + iommufd)의 GPU 메모리 버퍼 오버헤드가 측정 노이즈 이하로 나온 이유를, GPU 버퍼가 IOMMU에 올라가는 매핑 단위(페이지 크기)에서 확인한 결과다. 대상은 upcie-cuda 백엔드가 GPU 힙을 NVMe의 IOMMU 도메인에 매핑하는 경로다.

판정

Green2 MiB GPU 힙의 IOMMU 매핑 단위는 2 MiB다. uPCIe가 DMAMEM_CUDA_REGISTRY_GRANULARITY(2UL << 20)로 힙 전체를 iommu_map_pa_add 한 번에 등록하며, 이는 디바이스의 alloc_granularity(BAR1 large-page, L4에서 2 MiB)와 일치한다. IOMMU-off(uio) 경로에서는 매핑이 아예 없고 GPU BAR2 물리주소를 그대로 쓴다. 두 경우 모두 실행 중 per-page 번역이 생기지 않는다.

경로별 매핑

경로모드/트리거매핑번역
uio (IOMMU off)uio_pci_generic → UIO_LUT없음 — LUT가 BAR2 물리주소없음(identity)
vfio (IOMMU on)vfio-pci+iommufd → VFIO_CDEViommu_map_pa_add 1회, 2 MiB × N (1 GiB → 512)IOTLB 2 MiB leaf
dma-buf export/misc import (참고)dmabuf_import_attach(레거시)64 KiB × N 열거 — 매핑 단위 아님없음

검증

  • 코드: xnvme_be_upcie_cuda_dev.c의 _cuda_dev_dmem_init()이 xnvme_be_upcie_gpu_map_required()(= 모드 != UIO_LUT)로 분기한다. vfio면 dmamem_from_cuda_iommu_map_pa() → dmamem_register() → bulk iommu_map_pa_add(), 단위 DMAMEM_CUDA_REGISTRY_GRANULARITY = 2 MiB (upcie/dmamem_cuda.h). uio면 state->dmem이 BAR2 물리주소 LUT를 그대로 쓴다.
  • ftrace: tasks/trace_iommu_gpu.yaml로 iommu:map/iommu:unmap을 덤프. 2 MiB-aligned IOVA·물리주소의 superpage leaf가 관찰된다(Intel VT-d는 2 MiB 정렬 연속 범위를 2 MiB 페이지 하나로 매핑).
  • kprobe(별도 머신): RTX PRO 4000 Blackwell, Linux 6.8, intel_iommu=on에서 1 GiB 버퍼가 iommu_map 1회로 pgsize=2 MiB, pgcount=512, 페이지테이블 level 2에 기록됐다. BAR 주소 0x480f600000이 2 MiB 정렬이나 1 GiB 정렬은 아니라, VT-d가 1 GiB를 지원해도 2 MiB가 최대다.
  • probe: tasks/probe_dmabuf_import.yaml의 GET_MAP은 misc(무 IOMMU) 64 KiB × 16384와 --bdf 단일 세그먼트를 보여준다. 둘 다 export 측 뷰일 뿐 매핑 단위가 아니다.

왜 오버헤드가 안 보이는가

  • vfio: attach 시 map-once(2 MiB superpage), 실행 중 unmap이 없어 iommu.strict=1의 즉시 invalidation이 발동하지 않는다.
  • uio: 번역 자체가 없다.
  • 두 경우 모두 per-page walk가 없다. read 128K는 qdepth 1에서 이미 GPU PCIe 링크를 포화시켜, 그 구간 delta 0%는 링크가 말한 것이다.

한계

  • 2 MiB는 uPCIe가 힙을 등록하는 단위이자 L4의 alloc_granularity다. 다른 GPU/드라이버에서 이 값이 다르면 매핑 단위도 달라질 수 있다.
  • kprobe 수치는 RTX PRO 4000 Blackwell에서 측정한 것으로, 위 코드·ftrace(sid) 결과와 별개 머신이다.
